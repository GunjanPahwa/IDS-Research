# Feature Analysis

This document analyzes the compatibility of the feature spaces across our six datasets to evaluate the feasibility of cross-dataset generalization.

## 1. Taxonomic Mapping of Key Network Features

The table below maps core network flow characteristics to their corresponding column names in each dataset.

| Semantic Concept | KDD99 / NSL-KDD | UNSW-NB15 | CIC-IDS2017 / 2018 | UWF ZeekData |
| :--- | :--- | :--- | :--- | :--- |
| **Connection Duration** | `duration` | `dur` | `Flow Duration` (or `Flow_Duration`) | `duration` |
| **Protocol Type** | `protocol_type` (str) | `proto` (str) | `Protocol` (int) | `proto` (str) |
| **Source Bytes** | `src_bytes` | `sbytes` | `Total Length of Fwd Packets` | `orig_bytes` |
| **Destination Bytes**| `dst_bytes` | `dbytes` | `Total Length of Bwd Packets` | `resp_bytes` |
| **Source Packets** | Not present | `spkts` | `Total Fwd Packets` | `orig_pkts` |
| **Destination Packets**| Not present | `dpkts` | `Total Backward Packets` | `resp_pkts` |
| **Connection State** | `flag` (SF, S0, REJ...) | `state` (FIN, INT...) | Not present (has individual flag counts) | `conn_state` (SF, S0, REJ...) |
| **Service Category** | `service` (http, smtp) | `service` (http, smtp) | Not present (Destination Port only) | `service` (http, smtp) |
| **Destination Port** | Not present | Not present (in split) | `Destination Port` | `dest_port_zeek` |

## 2. Categories of Feature Equivalence

### Type 1: Exact Common Features (Identical Names & Semantics)
- **KDD99 vs. NSL-KDD**: The first 41 columns of KDD99 and NSL-KDD are identical in name, order, and datatype. For example, `duration`, `protocol_type`, `service`, `flag`, `src_bytes`, and `dst_bytes` match exactly.
- **CIC-IDS2017 vs. CSE-CIC-IDS2018**: The feature spaces generated by CICFlowMeter are highly identical, containing matching statistics like `Flow Duration`, `Total Fwd Packets`, `Total Backward Packets`, and various packet length statistical measures (mean, standard deviation). There are minor naming variance differences (such as spaces in 2017 vs. underscores in some versions of 2018, e.g., `Destination Port` vs. `Destination_Port`).

### Type 2: Semantically Equivalent Features (Different Names)
- **Duration**:
  - KDD99/NSL-KDD: `duration` (seconds, float/int)
  - UNSW-NB15: `dur` (seconds, float)
  - CIC-IDS2017/2018: `Flow Duration` (microseconds, int) -> Requires division by $1,000,000$ to map to seconds.
  - UWF ZeekData: `duration` (seconds, float)
- **Bytes Sent/Received**:
  - KDD99: `src_bytes` (sent), `dst_bytes` (received)
  - UNSW-NB15: `sbytes` (sent), `dbytes` (received)
  - CIC-IDS2017: `Total Length of Fwd Packets` (sent), `Total Length of Bwd Packets` (received)
  - UWF ZeekData: `orig_bytes` (sent), `resp_bytes` (received)
- **Handshake Connection State**:
  - KDD99: `flag` (e.g., `SF`, `S0`, `REJ`) maps directly to UWF ZeekData's `conn_state` (which uses the exact same Zeek-originating abbreviations). UNSW-NB15's `state` contains similar connection states (e.g., `FIN`, `INT`, `CON`) but with slightly different categorical structures.

### Type 3: Features That Cannot Be Mapped (Disjoint Features)
- **Host-Based Connection Window Statistics**: KDD99 and NSL-KDD extract connection count aggregates over time windows (e.g., `count`, `srv_count`, `dst_host_count`, `dst_host_same_srv_rate`). These features are specific to KDD99's collection script and do not exist in the flow exports of CICFlowMeter or Zeek logs.
- **Packet Length Distribution Statistics**: CICFlowMeter extracts statistical metrics such as `Fwd Packet Length Std`, `Flow IAT Variance`, and `Packet Length Mean`. Neither KDD99 nor UWF ZeekData records individual packet size variance within their standard tabular features.

### Type 4: Dataset-Specific Features
- **NSL-KDD**: `difficulty_score` (representing how many base classifiers incorrectly classified this row in human design).
- **UNSW-NB15**: `trans_depth` (pipelined HTTP depth), `response_body_len` (size of HTTP response bodies).
- **UWF ZeekData**: `history` (Zeek history flags tracking packet header flags), `community_id` (standardized connection hash), `uid` (unique Zeek flow identifier string).

## 3. Conclusions on Cross-Dataset Experiments

1. **High-Fidelity Mappings**:
   - **KDD99 $\leftrightarrow$ NSL-KDD**: Fully compatible (41 common features).
   - **CIC-IDS2017 $\leftrightarrow$ CSE-CIC-IDS2018**: High compatibility (77 common features, requires string normalization to align column names).
2. **Low-Fidelity Mappings**:
   - **UNSW-NB15 $\leftrightarrow$ CIC-IDS2017 / KDD99**: Can only map a very small subset of 5-10 core features (duration, protocol, bytes, packet counts). Running cross-dataset experiments across these groups will require training models strictly on this minimal common feature space.
